# Spec — url-to-audio（视频链接转音频 skill）

- 状态：Draft（本文件为本地 spec，尚未发布到 issue tracker）
- 日期：2026-09-21
- 来源：grill-with-docs（grilling + domain-modeling）会话，覆盖 Q1–Q7 决策

## Problem Statement

用户经常手持一个视频链接（典型如 B 站 `https://www.bilibili.com/video/BVxxxx`），想把其中的声音提取成可用的音频文件（用于听、剪、转写等）。现有做法要么手搓 `yt-dlp` 长参数易错，要么拿到低音质音轨，要么音频落到用户找不到的目录。需要一个可靠、保真、可解释的 skill 来自动完成「链接 → 本地音频文件」，且默认输出到桌面。

## Solution

一个名为 `url-to-audio` 的 skill：用户给出视频链接（可选指定格式/分P/登录方式），skill 调用封装脚本 `extract_audio.sh`，最优化地把音轨提取成本地音频，默认落盘到桌面（写不进自动回退 `~/Downloads`），并回传结构化结果（输出路径、标题、时长、格式）。默认路径保真最优（m4a 原样复制、零重编码），默认读 Chrome 登录态以争取更高音质档位，失败时匿名回退。

## User Stories

1. 作为普通用户，我想粘贴一个 B 站视频链接并说「提取音频」，让 skill 自动把该链接的音频保存为本地文件，以便我直接使用。
2. 作为普通用户，我希望音频默认保存到我的桌面，以便我能轻松找到。
3. 作为 macOS 用户，如果桌面因系统隐私（TCC）写不进，我希望音频自动落到 `~/Downloads` 并明确告诉我实际位置，而不是报错让我手动改。
4. 作为用户在 B 站登录过，我希望 skill 默认尝试读我的 Chrome 登录态来获取更高音质音轨，以得到比匿名更好的音频。
5. 作为用户但我的登录信息在其他浏览器（Safari/Firefox），我希望显式传 `-b <browser>` 指定来源，从而也能拿到高音质。
6. 作为不想暴露浏览器的用户，我希望用 `-c <cookiefile>` 传入 Netscape 格式 cookie 文件来鉴权，避免每次读取浏览器登录态。
7. 作为没有登录态的用户，我希望无登录信息时仍能匿名提取音频，而不是被拒绝。
8. 作为喜好无损的用户，我希望显式指定 `-f flac/alac/wav` 时能得到对应容器，即使源是有损也只换容器。
9. 作为默认用户，我希望不指定格式时默认得到 m4a 原样复制（最保真、体积小、免二次编码），而不是默认变成 flac/wav。
10. 作为面对合集/多分P的用户，我希望默认只提取链接所指向的那一个 P，避免不知情拉取全部分P导致下载量暴增。
11. 作为确实想要整个合集的用户，我希望显式说「整个合集/全部P」时才批量提取。
12. 作为用户，我希望明确知道提取完成后音频的完整路径、标题、时长、格式，以便定位文件。
13. 作为用户，我希望下载过程保持静默、不刷进度，完成时收到明确的结果提示。
14. 作为用户，当提取失败（404/需登录/版权/地区限制）时，我希望收到清晰的失败信息，而不是只看到一堆 yt-dlp 原始报错。
15. 作为用户，如果缺失 `yt-dlp`/`ffmpeg`，我希望收到 `brew install` 的安装提示，而非被静默改动或含糊报错。
16. 作为用户，我希望知道「清晰度和音频质量是两个独立维度」——切到 4K 不代表音频更好；登录才有机会拿更高音质档。
17. 作为用户，我希望登录态读取只在本机发生、不外传，且能用 `-b`/`-c` 改变鉴权来源或回到匿名。

## Implementation Decisions

- 单一封装入口：`scripts/extract_audio.sh` 封装所有 `yt-dlp`/`ffmpeg` 调用，agent 不手搓长参数。
- 默认输出格式：`auto` → m4a 原样复制（零重编码）；`-f` 可选 `mp3|flac|alac|wav`。无损格式为显式选项，对有损源只改容器。见 ADR-0001。
- 默认格式选择依据（保真策略）：对 AAC/m4a 源，`-f "ba/b"` + remux 即为最优保真路径；不默认转 flac/wav。
- 输出目录：默认 `~/Desktop`，脚本 `mkdir -p` 并探测 TCC（写权限）；写不进自动回退 `~/Downloads` 并告知实际落盘位置；`-o <dir>` 可显式覆盖。
- 分P/合集：默认 `--no-playlist`，只取链接指向的 P；用户显式要求全集时才 `-p N` 或去掉 `--no-playlist`。
- 登录态鉴权（见 ADR-0002，覆盖原「默认不读 cookie」红线）：
  - 默认 `-b chrome`：读 Chrome 登录态提音质；读不到/失效时自动匿名回退继续抓取。
  - 其他浏览器由用户显式传 `-b safari|firefox` 等。
  - `-c <cookiefile>` 支持 Netscape 格式 cookie 文件，用于不想暴露浏览器或无头场景。
  - 失败判定：cookie/登录相关错误 → 匿名重试；TCC/权限错误 → 回退 `~/Downloads` 重试；其余 → 原样回传错误。
- 进度可见性：`--no-progress` 静默执行；完成才回传结果摘要，失败给失败信息。
- 结果回传：输出 `### 提取结果 ###` 块含 `outdir / title / duration / format`，供 agent 复用。
- 依赖处理：探测 `yt-dlp`/`ffmpeg`，缺失即打印 `brew install` 提示并 exit 127，绝不自动安装。
- 安全与隐私：默认读 Chrome 登录态获取；读取仅本机 cookie 供 yt-dlp 使用，不外传；不写入任何 token/账号信息到 skill 或脚本。

## Testing Decisions

- 验收方式：**端到端真实调用**。用一个真实 B 站视频链接执行 `extract_audio.sh`，核对：
  - 音频文件确实落盘（默认桌面或回退后的 `~/Downloads`），扩展名符合格式。
  - 元数据块正确回传（title/duration/format 非空或 `<unknown>` 兜底）。
  - 默认 m4a 零重编码路径生效（不产生二次编码）。
  - 匿名回退路径（无 Chrome 登录态时不中断、仍出音频、提示可登录提音质）。
  - 缺失依赖时输出 `brew install` 提示并 exit 127。
  - `-h` 帮助、非法格式 `-f m4a2` exit 2 等参数路径。
- 由于项目无自动化测试基础设施（纯 bash skill），不引入测试框架，以手工端到端验收清单为准。
- 回归关注：掉用真实网络与登录态，避免在无网络环境做断言。

## Out of Scope

- 批量/队列式多链接处理（每链接独立一次调用）。
- 视频画面下载或转码（本 skill 只取音频）。
- 自动安装依赖或自动抓取浏览器登录信息（均为显式/用户确认后行为）。
- 登录账号管理、token 存储、成员/会员权益逻辑。
- 非 yt-dlp 支持平台的自研解析。
