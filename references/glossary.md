# 术语表 — URL 转音频 (url-to-audio)

> 术语表（仅词汇，不含实现细节）。需要时按需加载。

## Glossary

| 术语 | 定义 |
| ---- | ---- |
| **视频链接 (video URL)** | 指向单个视频媒体资源的地址，如 `https://www.bilibili.com/video/BVxxxx`。可携带查询参数（如 Bilibili 的 `p=N`）。 |
| **分P (part)** | 一个链接下同级的多段视频，每段一个 P（Part）。链接不写 `p=` 时默认指向 P1；写 `p=N` 时指向第 N 段。 |
| **音轨 (audio track / format)** | 视频中可独立提取的音频流。源站常见为 AAC（封装为 m4a，有损）。"最保真的音轨"指该链接下码率最高的一条。 |
| **提取 (extract)** | 从视频链接抓取并保存音轨到本地的过程。核心由 `yt-dlp` 完成。 |
| **原样复制 (zero re-encode)** | 把源音轨封装进目标容器而不重编码——已是最保真路径。源为 AAC/m4a 时，`m4a 原样复制` 不劣于任何后续转码结果。 |
| **转码/再编码 (re-encode)** | 用 ffmpeg 对已提取音轨重新编码以改变格式（如 m4a→mp3/flac/wav）。对**有损源**，转码不会恢复丢失信息，只会改变容器或减少体积。 |
| **无损格式 (lossless container)** | FLAC / ALAC / WAV / AIFF 等。它们能"无损"承载内容，但**不能凭空恢复有损源的细节**；仅当源站原生提供无损音轨时才有意义。 |
| **登录态 (cookies)** | 复用浏览器登录 cookie（如 Chrome/Safari/Firefox）以访问需登录内容并取得更高音质音轨。**默认尝试读取 Chrome 登录态**；读不到时匿名回退。 |
| **音质档位 (audio tier)** | B 站音轨的独立等级（约 64kbps → 132kbps → 192kbps「High-Res」/无损）。档位高低由**登录态/大会员**决定，与画面分辨率是**两个独立维度**——切到 4K 不代表音轨更好。登录（或大会员）才可能取到更高音频档。 |
| **默认浏览器 (default browser)** | 未显式传浏览器时默认读 **Chrome** 登录态；其他浏览器由用户显式传 `-b <browser>`/`-c <cookiefile>` 决定。 |

## 边界/约定

- 默认输出为 **m4a 原样复制**，这是保真与体积的最优默认。
- 无损格式（flac/alac/wav）是**显式选项**，非默认；对无源无损支持的站会回落 m4a。
- 每一链接只提取**链接所指向的那一个 P**，不批量提取全部分P。
- **cookie 默认尝试读取 Chrome 登录态**（换取更高音质）；无登录数据时匿名回退继续获取；若失败则输出失败信息并提示用户可登录后重试以提音质。其他浏览器需用户显式传入。
