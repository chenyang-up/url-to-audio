# ADR-0002: 默认读取 Chrome 登录态以换取更高音质

- 状态：Accepted
- 日期：2026-09-21
- 决策者：用户（Q5/Q6/Q7 grilling rounds）

## 背景

B 站音质档位与登录态/大会员强相关：更高档音轨（192kbps「High-Res」/无损）通常需要登录（或大会员）。此前设计（ADR-0001 前提、glossary 旧口径）默认 `匿名抓取`，仅在用户显式传入浏览器时才读取 cookie——即「默认不主动读浏览器」的隐私红线。

当用户明确表达「想要更高音质」时，匿名抓取往往只到 132kbps，无法解锁更高档。为满足这一核心诉求，需要重新权衡「隐私」与「音质」。

## 决策

- **默认尝试读取 Chrome 登录态**（`--cookies-from-browser chrome`），以换取更高音质音轨。
- 读不到登录数据 / Chrome 无会话时，**匿名回退继续获取**（不因无登录而失败；仅拿不到高音质档）。
- 提取失败时，输出失败信息，并提示「登录后重试可提音质」。
- 其他浏览器由用户显式传入（`-b <browser>` 或 `-c <cookiefile>`）。

## 后果

- 正向：默认路径即可解锁更高音质；匿名回退保证兼容性（无登录也能出音频）。
- 负向：**打破了「默认不主动读浏览器」的隐私默认**。每次提取会尝试读取本机 Chrome 的登录 cookie。
- 缓解：读取的是用户本机浏览器登录态，不外传；用户可用 `-b`/`-c` 改换来源或改回纯匿名；读取范围仅 cookie 供 yt-dlp 使用。

## 备选方案

- 维持默认匿名（Q5 原始红线）：尊重隐私但拿不到高音质，与用户核心诉求冲突——已否决。
- 每次询问是否读 cookie：过于打扰，且每次下载都要交互——已否决。
